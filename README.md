# Шаблон Magisk-модуля с overlayfs

**Русский** · [English](README_EN.md)

Чистый модуль-заготовка: кладёте свои файлы в `module/ovl/`, собираете zip
одной командой — и файлы появляются в `/system`, `/vendor`, `/product` и т. д.
Без Magic Mount, без тысяч лишних монтирований и без бутлупа из-за них.

Механизм взят из модуля ArkamysAudio (v2.0-beta.5 … beta.9), где он был
отлажен и проверен на реальном телефоне: TECNO SPARK 9 Pro, Android 12,
ядро 4.19, MediaTek, Magisk 30.7.

Работает с Magisk (v20.4+), KernelSU и APatch.

---

## Какую проблему решает

### 1. Бутлуп из-за переполнения области системных свойств

Когда модуль добавляет в **существующую** папку **новый** файл или папку
(например, свою `/vendor/etc/myconfig/` или новое приложение в
`/system/priv-app/`), Magisk (Magic Mount) не может просто «дописать» файл:
он делает на месте этой папки tmpfs и **отдельно монтирует каждый соседний
файл** оригинальной папки.

На каждое такое монтирование `init` создаёт системное свойство
`dev.mnt.blk.*`. Свойства хранятся в области фиксированного размера.
Реальные цифры с TECNO SPARK 9 Pro (beta.1 ArkamysAudio):

| Что добавил модуль                     | Сколько монтирований это дало |
|----------------------------------------|------------------------------:|
| новая папка в `/vendor/etc`            | 649 |
| новая папка в `/system/etc`            | 546 |
| новый jar в `/system/framework`        | 351 |
| новый бинарник в `/system/bin`         | 221 |
| новое приложение в `/system/priv-app`  | 157 |

Итого ~2000 свойств. Область свойств закончилась, `system_server` упал на
`SystemProperties.set(...)` → `__system_property_add failed` → **бутлуп**.
Модуль при этом «ничего плохого не делал» — просто добавил пару файлов.

**Этот шаблон** вместо этого делает **одно** монтирование overlayfs на
каждую затронутую папку. Те же файлы ArkamysAudio после перехода на overlay:
4 overlay + 1 образ вместо ~2000 монтирований, 0 ошибок свойств, телефон
грузится.

### 2. Overlayfs на Android «просто так» не работает — здесь это уже решено

Если попытаться сделать overlay самому, по очереди упрётесь в три стены
(все три были пойманы на реальном устройстве):

| Попытка                                 | Ошибка                       | Причина |
|-----------------------------------------|------------------------------|---------|
| слой прямо в `/data/adb/modules/...`    | `Invalid argument` (EINVAL)  | `/data` — f2fs с шифрованием/casefold, overlayfs его не принимает |
| слой в tmpfs (`/dev/...`)               | `Operation not supported`    | у tmpfs нет xattr, SELinux не может прочитать метки |
| слой в ext4-образе на loop-устройстве   | `I/O error` при монтировании | SELinux запрещает потоку loop (домен `kernel`) читать файл с меткой `system_file` |

Рабочая схема шаблона: при загрузке файлы из `ovl/` копируются в
ext4-образ `ovl.img` (как `modules.img` в KernelSU), образу ставится метка
`adb_data_file`, а `sepolicy.rule` разрешает ядру его читать. Каждому файлу
слоя выставляются правильные владелец, права и SELinux-метка, после чего
образ перемонтируется только для чтения и поверх реальных папок ставятся
overlay.

### 3. Плюсы

- **Нет бутлупа из-за свойств** — одна точка монтирования на папку, сколько
  бы файлов вы ни добавили.
- **Меньше следов**: меньше точек монтирования — проще и быстрее загрузка,
  меньше мусора в `/proc/mounts`.
- **Правильные метки SELinux автоматически**: новый файл получает метку
  файла, который заменяет, или ближайшей существующей родительской папки.
  Для особых случаев (бинарник HAL) — одна строка в `ovl.conf`.
- **Скрытие системных приложений/файлов** без `REPLACE` (который в Magisk
  тоже раздувает число монтирований) — через whiteout overlayfs.
- **Только чтение**: образ и overlay смонтированы `ro`, система не может
  случайно что-то в них записать.
- **Безопасное удаление**: модуль ничего не меняет в разделах. Отключили или
  удалили модуль в приложении → после перезагрузки всё как было.
- **Правка без пересборки**: изменили файл в
  `/data/adb/modules/<id>/ovl/` → перезагрузка → изменения на месте
  (слой пересобирается при каждой загрузке).
- **Диагностика в один тап**: кнопка «Действие» в приложении Magisk/KSU
  показывает, какие папки смонтированы, число свойств `dev.mnt.blk` и лог.
- **Не ломает остальные модули**: в `module/system/` можно по-прежнему класть
  файлы для обычного Magic Mount (см. ниже, когда это уместно).

## Структура

```
overlay-module-template/
├── build.sh                ← собирает out/<id>-<version>.zip
├── tests/test_ovl.sh       ← проверка движка на ПК (без телефона)
├── docs/MAGISK_PROPOSAL.md ← как сообщить о проблеме разработчикам Magisk
└── module/                 ← это и есть содержимое zip
    ├── META-INF/...        стандартный установщик Magisk, не трогать
    ├── module.prop         id, имя, версия — ОБЯЗАТЕЛЬНО поменять
    ├── customize.sh        выполняется при установке (можно дописать своё)
    ├── post-fs-data.sh     Magisk: запускает ovl.sh при загрузке
    ├── post-mount.sh       KernelSU/APatch: запускает ovl.sh при загрузке
    ├── ovl.sh              движок overlay — обычно не трогать
    ├── ovl.conf            настройки движка
    ├── sepolicy.rule       правила SELinux для образа и меток
    ├── action.sh           кнопка «Действие»: статус и лог
    └── ovl/                ← ВАШИ ФАЙЛЫ, по реальным путям на телефоне
        └── system/etc/ovl_template/README.txt   (пример, удалить)
```

## Как собрать свой модуль — пошагово

### Шаг 1. Скопируйте шаблон

```sh
cp -r overlay-module-template my-module
cd my-module
```

### Шаг 2. Заполните `module/module.prop`

```properties
id=my_module
name=My Module
version=v1.0
versionCode=1
author=Ваш ник
description=Что делает модуль
```

`id` — уникальный, только латиница, цифры, `.`, `_`, `-`, начинается с буквы.
По нему модуль лежит в `/data/adb/modules/<id>`, а образ монтируется в
`/dev/ovl_<id>`. При каждом обновлении увеличивайте `versionCode`.

### Шаг 3. Удалите пример и положите свои файлы в `module/ovl/`

Путь внутри `ovl/` = путь на телефоне.

```sh
rm -r module/ovl/system/etc/ovl_template
```

| Хочу на телефоне                               | Кладу в                                              |
|------------------------------------------------|------------------------------------------------------|
| `/system/priv-app/MyApp/MyApp.apk`             | `module/ovl/system/priv-app/MyApp/MyApp.apk`         |
| `/system/etc/permissions/privapp-my.app.xml`   | `module/ovl/system/etc/permissions/privapp-my.app.xml` |
| `/vendor/etc/myconfig/settings.xml`            | `module/ovl/vendor/etc/myconfig/settings.xml`        |
| `/vendor/lib64/soundfx/libmyfx.so`             | `module/ovl/vendor/lib64/soundfx/libmyfx.so`         |
| заменить `/vendor/etc/audio_effects.xml`       | `module/ovl/vendor/etc/audio_effects.xml`            |
| `/system/bin/mytool`                           | `module/ovl/system/bin/mytool` (станет 0755 сам)     |
| `/product/overlay/MyRRO.apk`                   | `module/ovl/product/overlay/MyRRO.apk`               |

Пишите `vendor/...`, а не `system/vendor/...` — так понятнее. Но и
`system/vendor/...` тоже сработает: движок проходит по симлинку и монтирует
на реальную папку.

Правила:

- **Без пробелов** в именах файлов и папок (`build.sh` это проверит).
- **Нельзя класть файл прямо в корень раздела** (`ovl/system/myfile`,
  `ovl/vendor/newdir/...`, если `newdir` не существует). Overlay на весь
  `/system` или `/vendor` движок делать откажется — это слишком опасно. Такой
  путь будет пропущен с записью `refused target` в `ovl.log`, остальные
  файлы смонтируются как обычно. Кладите хотя бы на уровень глубже
  существующей папки (`/system/etc/...`, `/vendor/etc/...`).
- Скрипты с концами строк Windows (CRLF) не запускаются — `build.sh` их
  найдёт.

### Шаг 4. Настройте `module/ovl.conf` (если нужно)

```sh
# Папки для overlay. Пусто = определяются сами по ovl/ (рекомендуется).
OVL_TARGETS=""

# Спрятать существующие файлы/папки (whiteout), через пробел:
OVL_HIDE="/system/app/MusicFX /system/priv-app/AudioFX"

# Свои SELinux-метки, по одной "путь=метка" на строку.
# Нужны, например, для исполняемого файла нового HAL-сервиса:
OVL_LABELS="/vendor/bin/hw/vendor.my.hal-service=u:object_r:hal_my_default_exec:s0"

# Размер ovl.img в МиБ. 0 = (размер ovl/ × 2) + 8.
OVL_IMG_MB=0
```

Если используете в `OVL_LABELS` метку, которой нет в `sepolicy.rule`,
добавьте её туда в строку `... labeledfs filesystem associate`, иначе
`chcon` не сможет её выставить.

### Шаг 5. Свои действия при установке и при загрузке

- Проверки при установке (версия Android, архитектура, конфликтующие
  модули) — в конец `module/customize.sh`. Там доступны `ui_print`,
  `abort`, `$API`, `$ARCH`, `$MODPATH`, `set_perm`, `set_perm_recursive`.
- Код после загрузки системы — создайте `module/service.sh` (обычный
  скрипт Magisk, запускается в фоне).
- Свои правила SELinux — дописывайте в `module/sepolicy.rule`.
- Системные свойства — `module/system.prop` (стандартно для Magisk).

**Не трогайте** строки, вызывающие `ovl.sh`, в `post-fs-data.sh` и
`post-mount.sh`. Если нужен свой код в post-fs-data — пишите его **после**
строки `. "$MODPATH/ovl.sh"`.

### Шаг 6. Сборка

На ПК с Linux/macOS, в WSL или в Termux:

```sh
sh build.sh
```

Получится `out/<id>-<version>.zip`. Скрипт проверяет `module.prop`,
синтаксис всех `.sh`, пробелы в путях и CRLF.

Без `build.sh` (например, на Windows) — просто запакуйте **содержимое**
папки `module/` в zip так, чтобы `module.prop` и `META-INF/` лежали в корне
архива, а не внутри папки `module/`.

Если меняли `ovl.sh`, прогоните тест движка:

```sh
sh tests/test_ovl.sh
```

### Шаг 7. Установка и проверка на телефоне

1. Magisk / KernelSU / APatch → Модули → Установить из хранилища → zip.
2. Перезагрузка.
3. В списке модулей нажмите кнопку **«Действие»** у вашего модуля. Должно
   быть примерно так:
   ```
   Overlay status:
   ok /system/priv-app
   ok /vendor/etc

   dev.mnt.blk properties: <десятки, а не тысячи>
   ```
   Если есть `fail` — смотрите лог ниже в том же окне и раздел «Неполадки».
4. Проверка вручную (в `su` или `adb shell`):
   ```sh
   grep ovl_ /proc/mounts            # образ на loop
   grep " overlay " /proc/mounts     # overlay на ваших папках
   ls -lZ /vendor/etc/myconfig/      # ваши файлы и их метки
   cat /data/adb/modules/<id>/ovl.log
   ```

## Когда класть в `ovl/`, а когда в обычный `system/`

| Ситуация | Куда |
|---|---|
| **Новый** файл или папка в существующей папке | `ovl/` — именно здесь Magic Mount и создаёт сотни монтирований |
| Скрыть приложение/файл | `OVL_HIDE` в `ovl.conf` (не `REPLACE`) |
| Заменить один **существующий** файл | можно и туда, и туда: Magisk для замены делает одно bind-монтирование. В `ovl/` — единообразно и с правильной меткой |
| Ядро без overlayfs | только `system/` (обычный Magisk) |

## Неполадки

| Симптом в `ovl.log` / `dmesg` | Что значит и что делать |
|---|---|
| `kernel has no overlayfs` | Ядро собрано без overlayfs. Шаблон не поможет; используйте обычный `system/` |
| `cannot mount .../ovl.img`, в `dmesg` `avc: denied ... scontext=u:r:kernel:s0` | Не применилось правило из `sepolicy.rule`. Проверьте, что файл есть в модуле, и переустановите модуль |
| `FAILED /x/y` + `Invalid argument` | Слой оказался на `/data`. Не меняйте пути в `ovl.sh` — слой должен быть в `ovl.img` |
| `FAILED /x/y` + `Operation not supported` / `no security xattr handler` | Слой оказался в tmpfs. Аналогично: не меняйте пути |
| `refused target /system` | Файл лежит прямо в корне раздела. Переложите глубже |
| Файл виден, но сервис/приложение не может его открыть, в logcat `avc: denied` | Неверная метка. Задайте правильную в `OVL_LABELS` и добавьте её в `sepolicy.rule` |
| Приложение из `priv-app` не стартует, `pm` не видит пакет | Не хватает whitelist-а привилегий: положите `privapp-permissions-*.xml` в `ovl/system/etc/permissions/` |
| Бутлуп | Зажмите «громкость вниз» при загрузке (безопасный режим Magisk отключит все модули) или удалите `/data/adb/modules/<id>` из recovery |

## Ограничения

- Нужен overlayfs в ядре (есть почти во всех ядрах Android 8+).
- Пути без пробелов.
- Нельзя добавлять файлы прямо в корень раздела.
- Если **другой** модуль через обычный Magic Mount добавляет файлы в ту же
  папку, поверх вашего overlay ляжет tmpfs Magisk. Такие пары модулей
  проверяйте вместе.
- На KernelSU в режиме overlayfs (не magic mount) исходной проблемы нет —
  шаблон там работает, но выигрыш небольшой. Главная польза — Magisk и
  сборки KernelSU/APatch с magic mount.
- `ovl.img` занимает место на `/data` (по умолчанию двойной размер `ovl/`
  плюс 8 МиБ).

## Что проверено

- Сам механизм (ext4-образ на loop, метка `adb_data_file`, правило для
  `kernel`, overlay на `/vendor/etc`, `/system/etc/permissions`,
  `/system/etc/sysconfig`, `/system/priv-app`, whiteout для MusicFX)
  работает на устройстве в ArkamysAudio v2.0-beta.5 … beta.9: TECNO SPARK 9
  Pro, Android 12, ядро 4.19, Magisk 30.7.
- Универсальный движок шаблона (`ovl.sh`: автоопределение папок, метки по
  ближайшему родителю, права, отказ от корня раздела, повторный запуск)
  проверен тестом `tests/test_ovl.sh` на ПК с заглушками. **На телефоне
  сам шаблон пока не запускался** — первым делом установите zip как есть и
  проверьте, что читается `/system/etc/ovl_template/README.txt`.
